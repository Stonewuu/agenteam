# 界面消息与运行日志

界面提示根据用户选择显示中文或英文。运行日志固定使用英文，原始异常、用户输入和供应商返回的业务内容保持原样；已有的敏感信息隐藏处理继续生效。

## 后端消息

消息保存在 `agenteam-server/src/main/resources/i18n/core/`，由 `META-INF/agenteam/messages.index` 登记。每个消息代码同时提供 `zh-CN` 和 `en`；动态内容使用 `{0}`、`{1}` 等参数，不在调用处拼接半句提示。

- `Messages.text` 生成当前请求语言的用户提示，包括异常、直接返回的工具结果和状态说明。
- `Messages.source` 读取固定原文，用于保存内置定义、计算版本摘要和匹配固定指令。不要让这些内容随请求语言变化。
- `Messages.log` 生成固定英文日志。日志中的 `{}` 继续由日志库填入参数，不要先拼接异常对象。
- 字段约束通过 `message = "{消息代码}"` 引用同一目录。参数名称也应使用对应语言的名称。

浏览器保存的语言选择优先于 `Accept-Language`（请求希望使用的语言）。请求结束后清理当前线程的语言状态；后台任务没有请求语言时使用中文。明确属于系统的历史提示可以在展示时翻译，不改写保存记录，不对用户正文调用消息翻译方法。

独立工具接口使用自身的 Java 标准语言资源，不依赖主应用。示例插件中的自定义名称和内容由插件维护，不按平台内置插件处理。

## 内置插件与前端

内置插件的原始名称、说明、翻译和外观共用 `catalog/builtin-plugins.json`。前端按资源来源和内置代码读取翻译，用户创建或导入的同名插件仍显示用户填写的内容。英文菜单保持简短，操作单个资源时使用单数名称。

修改语言资源后，在仓库根目录执行 `node scripts/i18n/sync-catalogs.mjs`，更新前端生成文件。自动检查使用同一命令的 `--check` 参数核对一致性。不要直接编辑生成文件。

后端语法树检查覆盖生产源码中的提示、日志、直接返回内容和约束引用，并核对消息代码是否存在。前端测试检查界面翻译、参数完整性、日志语言以及用户内容保留；新消息应沿用这些入口。
