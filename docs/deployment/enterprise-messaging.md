# 企业微信、飞书与定时通知（0.4.0）

AgenTeam 支持绑定企业微信或飞书账号、使用绑定账号登录，并按计划接收站内和平台通知。管理员在页面配置企业自建应用；程序使用该应用的身份向明确绑定的成员发送个人消息。应用密钥不需要写入服务器配置文件。

机器人聊天与岗位协作使用独立开关：成员可以向已绑定岗位的机器人提出任务，岗位在 AgenTeam 内部分工、交接和共享成果，再回传进展。启用方法见本文“机器人聊天与内部协作”；旧的企业微信自建应用不能充当专用智能机器人。

本次开发已用官方协议的模拟接口验证授权、发送及异常处理。真实平台应用审批、可见范围、手机与桌面授权跳转，以及真实消息接收，仍需配置完成后按本文末尾步骤确认。模拟服务只在测试源码中，正式应用没有模拟成功的开关。

## 一、部署前提

- 部署配套的前后端 0.4.0，保留原数据库、Redis 和持久目录中的 `security/application-keys.properties`（应用内容加密密钥文件）。更换或丢失原密钥会导致已经保存的应用凭据无法解密。
- 在部署目录的 `.env` 中将 `PUBLIC_URL` 设为实际公开的 HTTPS（加密网页连接）站点地址，例如 `https://agent.example.com`，不要附带子路径、查询参数或账号密码。此地址用于授权回调、企业登录链接及通知详情。只有本机开发允许回环地址使用 HTTP。
- 反向代理将 `/api/v1/` 转发到后端，保留现有会话和安全响应头；不记录回调请求的查询参数。平台授权会在回调地址中携带一次性授权码。
- 服务端能够访问企业微信和飞书官方接口。企业微信应用要求的可信 IP（可信网络出口地址）应填写服务器调用平台时的固定公网出口地址，不能填网页域名解析地址来代替。
- 首期支持中国区企业自建应用。成员需先有 AgenTeam 账号并加入目标企业；首次绑定须登录该本地账号。不会根据同名、邮箱或手机号码自动合并账号。

采用独立 Java 进程部署时，将属性 `agenteam.web.public-base-url` 设置为公开站点；使用 `container` 或 `production` 配置时，该属性由 `AGENTEAM_PUBLIC_ORIGIN` 提供。Compose（多容器部署工具）已经将 `PUBLIC_URL` 传入此环境变量。

## 二、管理员配置入口

- 企业管理员：进入目标企业的“企业管理 → 企业协作平台”。
- 社区版超级管理员使用同一个企业管理入口；支持多企业管理的商业版，还可从“平台管理 → 企业协作平台”选择要维护的企业。

“企业接入”按飞书、企业微信分别管理公司登录、成员绑定和个人通知；“岗位机器人”管理人事、财务等岗位。通常分别配置一个飞书和一个企业微信的企业接入，再按岗位添加机器人，不需要为每个机器人配置企业登录。已有多个企业接入会保留，升级不会自动关闭原登录或通知。

新增接入后先保存，再在“查看配置”复制本条接入的“授权回调地址”。接入编号生成后保持不变，因此应复制页面实际值。完成平台后台的安全设置后，回到页面点击“校验应用”；通过后点击“启用”。校验通过表示当次应用凭据和企业信息读取成功，首次通知是否能发送仍要单独测试。

“允许成员绑定账号”“允许已绑定成员登录”“允许发送通知”可以分别选择。更换应用密钥后，需要重新校验和启用；等待中的旧发送不会自动转用新密钥继续发送。

## 三、企业微信自建应用

1. 在企业微信管理后台建立自建应用，并把测试成员加入应用可见范围。
2. 取得企业 ID（`CorpID`）、该应用的 `AgentID`（数字应用编号）和该应用的 `Secret`（应用密钥）。在 AgenTeam 新增企业微信接入，填写这三项和接入名称。不要填写通讯录同步密钥或群机器人 Webhook（群消息接收地址）。
3. 在应用的网页授权和 Web 登录设置中，按企业微信要求配置可信域名、回调域名及所需的域名归属校验。域名来自页面生成的授权回调地址。需要在企业微信工作台直接打开时，可把 AgenTeam 页面或该接入的企业登录链接作为应用入口。
4. 配置应用调用接口所需的企业可信出口地址。网页授权和接口出口属于不同设置，两者都应满足平台要求。
5. 回到 AgenTeam 校验并启用。页面的每日消息上限是本应用额外施加的发送控制，默认 200；应按企业实际额度调整，平台自身额度仍然生效。

企业微信客户端内采用网页授权，桌面浏览器采用企业微信 Web 登录；取得的身份必须是应用所属企业的成员。通知通过应用消息发送，并提供站内通知详情链接。依据：[网页授权](https://developer.work.weixin.qq.com/document/path/91022)、[Web 登录](https://developer.work.weixin.qq.com/document/path/98152)、[获取访问凭证](https://developer.work.weixin.qq.com/document/path/91039)、[发送应用消息](https://developer.work.weixin.qq.com/document/path/90236)。

## 四、飞书自建应用

1. 在飞书开放平台建立企业自建应用，取得 `App ID`（应用编号）和 `App Secret`（应用密钥）。
2. 开启机器人能力，申请 `im:message:send_as_bot`（以应用的身份发消息）和 `tenant:tenant:readonly`（获取企业信息）权限。前者用于个人通知，后者供 AgenTeam 校验应用所属企业。将测试成员放入应用可用范围，发布应用版本并完成企业要求的审批。
3. 在 AgenTeam 新增飞书接入，填写应用编号、密钥及名称并保存。飞书企业标识由校验接口取得，无需手工猜测。
4. 在飞书应用的安全设置中，将页面生成的完整“授权回调地址”加入重定向 URL（授权完成后允许跳转的地址）列表；协议、域名和路径须与页面一致。
5. 回到 AgenTeam 校验并启用。绑定时使用网页授权获得当前用户身份；发送时使用应用访问凭证。

个人身份使用本应用内的 `open_id`（用户在该应用中的编号）。本期不读取手机号、邮箱和员工编号，不申请离线授权；获取基础用户信息接口无需额外字段权限。群自定义机器人不能替代此应用机器人完成个人授权和此接口的个人发送。依据：[发送消息及权限](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[获取企业信息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/tenant-v2/tenant/query)、[用户授权](https://open.feishu.cn/document/common-capabilities/sso/api/obtain-oauth-code)、[获取用户信息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/authen-v1/user_info/get)。

## 五、成员绑定、登录与通知选择

1. 用本地账号登录 AgenTeam，进入“个人设置 → 企业账号绑定”，选择所在企业，也可以访问当前企业的账号绑定页面。
2. 点击“授权并绑定”，在平台完成授权，回到本站核对正在绑定的本地账号及平台账号，然后确认绑定。若要求重新认证，输入当前本地账号密码后继续。
3. 开启“接收通知”。如果希望以后通过平台账号登录，再开启“允许使用此账号登录”。超级管理员仍使用本地登录维护全局账号。
4. 自动业务通知默认不会发往外部渠道；需要时在同页的通知类别选择中主动开启。创建定时通知时，另外逐人明确选择渠道，但仍须满足该成员允许接收通知的总开关。
5. 管理员可从“查看配置”复制企业登录链接给该企业已绑定成员使用。平台登录会话只能访问对应企业，不能据此访问同一账号加入的另一家企业。会话最长一小时、空闲最长三十分钟；本地成员或绑定失效后不能继续使用。

解除绑定后重新绑定会建立新的身份记录。已经排队的旧通知不会自动改投新绑定，避免发给后来换绑的账号。

## 六、发送测试通知与创建计划

应用启用且至少一位成员已绑定并允许接收后，管理员在接入卡片点击“测试通知”，选择测试成员并发送。测试正文固定，不使用业务内容。通过“发送记录”查看实际结果；“平台已接受”只表示平台接口明确接受，不能证明成员已读。

在用户端“我的计划”点击“创建计划”，操作选择“发送通知”，填写标题、正文、接收人、每位接收人的外部渠道及执行时间。每人都会有站内通知，可以再选企业微信和飞书；每个平台最多选择一个应用。一次最多五十名明确成员。普通成员只能给自己创建通知，向其他成员发送还需企业通知发送权限。

保存后可通过“立即执行”先检查，或等待计划时间。执行详情保留该次原始内容和逐人、逐渠道结果；以后修改计划不会改变已经触发的内容。通知计划无需智能体、模型或模型执行额度。

- 一人失效时，其余接收人继续处理；详情会说明该人的阻止原因。
- 某个渠道失败时，只重试符合条件的该渠道；成功渠道和站内通知不会重发。
- “结果未知”表示请求可能已被平台接受但系统没有取得确定结果。人工重试需要明确确认可能重复接收；超过可重试期限、接入或绑定变化时，页面不会允许继续重试。
- “停止本次”阻止尚未发起的工作。已保存的站内通知和平台已接受的消息保留；正在请求的平台结果返回后再汇总。暂停计划只影响未来触发，需要停止当前一轮时使用“停止本次”。

## 七、升级与暂停工作

已有部署更新前，请先保存数据库、应用配置与密钥，并按当前版本对应的升级步骤操作。企业消息的历史迁移保留原名称和内容，原有应用配置与成员绑定随数据库一同保留。

本版本迁移按以下顺序执行，不能改名或改写已经执行的脚本：

| 迁移 | 内容 |
| --- | --- |
| `V0.1.0.1__新增企业渠道与用户绑定.sql` | 应用、密钥、绑定、一次性授权、偏好及六项权限；实施时已执行，升级版本后保留原名 |
| `V0.1.1.1__新增通知渠道发送记录.sql` | 渠道发送、尝试历史、通知来源和后台工作类型 |
| `V0.1.1.2__扩展定时操作及通知接收人.sql` | 通用操作、通知目标及发生记录固定参数 |

旧智能体计划保留原编号、时间、输入、固定版本和重试设置；旧执行记录没有的原始参数明确保持为空。旧版只认识智能体计划，不能与新通知计划共同运行，也不能在产生新数据后直接换回旧程序。

已有服务升级时，先备份数据库和加密密钥，停止旧版调度进程，更新配套前后端，再启用新工作。可使用以下 `.env` 开关控制升级步骤，修改后须重新创建后端容器；它们不是页面中实时切换的选项。

| Compose 配置 | 独立进程环境变量 | 设为 `false` 的影响 |
| --- | --- | --- |
| `NOTIFICATION_ACTIONS_ENABLED` | `AGENTEAM_NOTIFICATION_ACTIONS_ENABLED` | 关闭通知操作的新建、修改、手动及到期提交。已有未提交通知被阻止，相关计划在到期检查时暂停；已排入渠道的发送另受下项控制 |
| `SCHEDULE_ACTION_WORKER_ENABLED` | `AGENTEAM_SCHEDULE_ACTION_WORKER_ENABLED` | 暂停智能体和通知的通用准备工作及通知结果扫描；到期检查仍可排队，已提交的智能体仍由原执行器处理 |
| `CHANNEL_DELIVERY_WORKER_ENABLED` | `AGENTEAM_CHANNEL_DELIVERY_WORKER_ENABLED` | 暂停领取新的外部发送工作，等待记录保留；不会撤回已经发起的请求 |

三个开关默认都是 `true`。若升级时先关闭，检查通过后恢复并重启后端。暂存过久的通知会按发送有效期结束，不能把停用再启用当成不限时补发。暂停后已经被自动关闭的计划需由用户重新启用。

紧急控制可先暂停通知计划并停用相关接入。需要停止所有后台维护（包括到期检查和清理）时，使用原有 `agenteam.maintenance.worker-enabled=false` 属性；恢复数据仍沿用项目的 `recovery` 环境配置。回退应使用兼容新表和新操作格式的版本，保留发送历史。

临时授权默认七天后删除；终态发送的请求副本默认三十天清除、尝试记录九十天清除、发送结果一百八十天后删除。可通过 `agenteam.integration.retention.oauth-days/payload-days/attempt-days/result-days` 属性调整，结果保留不得短于一百八十天；活动工作不会提前清理。原站内通知不因渠道清理而删除。

## 八、配置真实应用后的验收

依次完成以下操作即可，无需把真实密钥发送给开发者：

1. 两个平台分别校验并启用；使用本地普通测试成员完成授权、确认绑定。
2. 在桌面浏览器及平台客户端各走一次登录，检查进入正确企业；退出后仍可以本地账号登录。
3. 管理员向该成员发送测试通知，在平台中确认实际收到，并打开站内详情链接。
4. 创建同时选择两平台的一次性计划，等待到点，核对站内和两平台各一份；页面状态应与实际请求结果一致。
5. 暂停其中一个接入或关闭成员接收设置，确认后续发送出现具体原因；恢复后只重试仍符合条件的失败渠道。

如果授权被平台拒绝，先核对回调地址、发布状态、权限及测试成员可见范围；企业微信再核对可信出口地址。保留页面中的失败原因及发送记录编号用于定位，不导出密钥、访问令牌或带授权码的完整回调网址。

协议依据、测试样本和网络故障说明见[平台模拟协议记录](../../agenteam-server/src/test/resources/contracts/integration/README.md)，后续增加渠道和定时操作的方法见[开发说明](../../agenteam-server/docs/integration-scheduling.md)。

## 九、排查平台拒绝与网络异常

页面中的失败摘要用于指导操作；具体平台原因保存在后端日志。升级到包含本次修正的后端后，搜索 `IntegrationHttpClient`、`渠道平台返回错误` 或 `渠道请求异常`，再按接入编号和失败时间定位。不要只检查 HTTP（网络请求协议）状态：企业微信和飞书可能在 HTTP 状态为 200 时，通过响应内的业务错误码表示失败。

日志包含接入编号、请求方法、平台主机、不含查询参数的路径、HTTP 状态、平台错误码、平台原因，以及平台实际提供的排障编号。错误说明中的应用权限、出口地址、成员范围等内容会保留；密钥、访问令牌、授权码和回显的通知正文会隐藏。不会输出整个请求、响应、请求头或查询串。

网络中断会保留脱敏后的具体异常原因及完整堆栈；响应无法解析时保留 HTTP 状态和解析异常堆栈，不打印可能带凭证的原文。历史发送记录中已经保存的统一摘要不会自动变成平台原始原因，旧请求也无法凭空恢复当时未记录的信息。排查后再次尝试发送仍需要遵守页面原有的重复发送确认。

## 机器人聊天与内部协作

升级时保留数据库、文件和应用加密密钥。聊天与协作默认关闭，不会因为已有登录或通知接入就开始消费群消息。首次开启后，只配置指定的测试机器人和测试群；通过收发验证后再增加业务群。

在部署目录的 `.env` 配置以下开关，然后更新应用容器：

```dotenv
CHAT_ENABLED=true
CHAT_FEISHU_ENABLED=true
CHAT_WECOM_AIBOT_ENABLED=false
COLLABORATION_ENABLED=true
CHAT_WORKER_ENABLED=true
```

独立 Java 进程使用对应的 `AGENTEAM_CHAT_ENABLED`、`AGENTEAM_CHAT_FEISHU_ENABLED`、`AGENTEAM_CHAT_WECOM_AIBOT_ENABLED`、`AGENTEAM_COLLABORATION_ENABLED` 和 `AGENTEAM_CHAT_WORKER_ENABLED` 环境变量。对外任务链接沿用 `PUBLIC_URL`；独立进程设置 `AGENTEAM_CHAT_PUBLIC_BASE_URL` 为同一公开站点。

1. 为需要协作的每个岗位发布智能体版本，配置内置“团队协作”插件及岗位实际需要的业务工具。任务发起人成员必须有使用资格并已雇佣相应智能体。
2. 在“企业协作平台 → 岗位机器人 → 添加机器人”选择平台，填写机器人的应用编号和密钥，选择智能体并填写岗位名称，点击“添加并启用”。新任务默认使用最新发布版本，固定版本和接收方式在高级设置中。创建中途失败会保留已完成的配置，关闭后可从列表“继续配置”；不需要再到另一个页面关联智能体。一个实际机器人只绑定一个岗位；在平台创建机器人、加入群仍需由管理员操作。
3. 飞书选择长连接或回调接收方式，并在飞书后台完成接收消息的事件订阅。长连接不需要公开接收地址；回调方式先保存校验令牌和加密密钥，再复制该机器人实际回调地址。签名头和原始请求正文必须完整到达后端，不能用登录授权回调地址代替消息回调地址。
4. 企微选择“企微智能机器人”，填写该机器人的 Bot ID（专用机器人编号）及 Secret（专用密钥）。此接入只提供专用聊天连接与配对，不提供原自建应用的网页登录或个人通知能力。没有专用机器人身份时保持此平台关闭。
5. 成员登录自己的群策账号，在“个人设置 → 企业账号绑定”授权绑定本人飞书账号，并在确认页选择“允许通过此账号使用智能体”。同一群策企业中、经过平台核验属于同一飞书企业的应用，可通过平台实际返回的 union_id（同服务商下的跨应用用户标识）识别同一成员，不需要逐个机器人绑定。不能用应用内 open_id（仅该应用可识别的用户编号）、昵称或邮箱跨应用匹配。缺少跨应用标识的旧绑定仍只适用于原应用，可重新授权取得标识。企微专用机器人仍使用一次性配对码，在与该机器人的私聊中完成配对；目前不能把普通企微应用的个人绑定直接用于专用机器人。
6. 管理员从机器人的“更多 → 连接检查 → 测试收发消息”选择测试会话和已绑定成员。生成接收测试后，由所选成员在该会话提及机器人并发送页面上的测试文字；文字发送、文件和历史读取分别验证，排入发送队列不代表平台已接受。列表不再平铺检查项。
7. 飞书机器人加入新群后，直接 @ 已启用的机器人即可开始，无需到网页刷新或启用。已订阅的入群事件会提前接入；没有入群事件时，首次 @ 消息也会自动接入并继续处理。已有共同接收验证的多个机器人可在新群复用该验证；尚未具备条件时由指定机器人接收，其他机器人会提示应 @ 哪个入口。企业微信仍在“聊天会话”选择参与岗位并保存。成果公开方式保留明确选择，任务次数和接收方式位于高级设置。管理员保存设置后按其选择执行，自动接入不会恢复已停用的群或重新加入已排除岗位。
8. 成员在群中明确提及接收机器人提出任务，也可同时指定所需岗位；在 AgenTeam 的“协作任务”查看分工、成果和回传状态。飞书可回复已关联任务的消息；企微补充要求时，在消息正文写出机器人回传的 `GC-` 开头任务编号。也可直接在任务页面补充要求。系统按明确的任务关联继续，不根据群里最近一次发言猜测。

任务交接由 AgenTeam 内部完成，群中展示的岗位进展不承担调度作用。机器人自己的消息、其他机器人消息、撤回和表情事件均不会触发新任务。更换智能体版本只影响新任务；旧任务继续使用开始时的版本和原发起人权限。

自动接入的飞书群会直接在原话题回复答案和选定的成果文件，无需再打开网页查看回答。已有自动接入的群在下一次消息到达时也会采用这个默认方式；旧任务继续追问时，原发起人明确选过的仅链接方式仍会保留。管理员手动设置的群按其成果公开范围执行，可选择仅返回链接。平台接收成功不表示所有群成员已读；发送失败可在管理页面按明确失败状态重试，不会让智能体重新执行一遍。发送结果未知时先核实平台实际情况，页面不会提供强制重复发送入口。

机器人的“更多 → 连接设置”用于查看授权地址、更换密钥和重新校验，不再出现第二次关联智能体。岗位对话顶部的“协作任务”可返回所属任务，补充要求、停止任务及查看各岗位成果均在任务页面完成。

本机测试账号授权时，飞书“安全设置 → 重定向 URL”填写页面生成的完整授权回调地址，例如 `http://localhost:3000/api/v1/auth/channel-callbacks/接入编号`。协议、主机、端口与路径保持一致，授权前后使用同一浏览器和同一群策访问地址；`localhost` 与 `127.0.0.1` 的登录会话不同。这个地址由用户浏览器访问，仅适用于本机测试；机器人长连接接收消息不依赖该地址，HTTP 事件回调则需要飞书服务器可以访问的公开地址。

停止聊天可关闭 `CHAT_ENABLED`；停止新的协作执行可关闭 `COLLABORATION_ENABLED`，后台会处理仍在执行的岗位。关闭 `CHAT_WORKER_ENABLED` 则暂停整个聊天后台处理，不应用它代替正常取消任务。任务已完成的外部业务操作和已保存成果不会因关闭开关或取消任务自动撤销。

无需审批且成员已有使用权限的岗位，会在首次实际工作时自动建立雇佣关系；不需要先到员工广场逐个雇佣。已暂停、已解除或需要审批的员工仍按原有选择处理。新建机器人协作任务默认使用“完全访问”，后续岗位也沿用；历史任务保留原来的执行策略，先前产生的待确认操作不会自动批准。

选择“直接回复内容”时，智能体提出的补充问题和选项直接发到来源会话；选择“仅发送链接”时，只发送待补充提醒和任务链接。飞书私聊直接回复即可继续；群聊同一任务的确认、问题、进度和成果都集中在原话题，原发起人回复话题并 @ 接收任务的机器人即可继续。企微群聊回复需带任务编号。

新建私聊任务默认把完整答复和选定的成果文件交付给已绑定的原发起人，不必再到平台查看答案；较长回复会分段，超过消息长度范围时发送完整回答文件。群聊仍遵守管理员的成果公开设置和原发起人的选择。协作岗位每轮结束不会再额外发送普通对话的完成通知。

收到最终答复后仍可继续追问。私聊直接发送后续内容或回复具体答案，群聊回复原任务消息或话题并 @ 机器人；由原发起人继续同一任务，保留岗位对话与已有成果。需要完全独立处理时，以“新任务”开头。已取消的任务不会自动恢复。

启用前至少确认：真实成员的提及只创建一个任务、重复事件不重复执行、原账号解绑后不能继续操作、完全访问不扩大资源和文件权限、机器人退群后不继续发消息。多个独立机器人、企微专用机器人及附件能力必须分别用实际环境验收，不能用一个飞书机器人的文字发送结果代替。

### 成员自主选择回复方式

新发现的会话默认允许成员选择，已有管理员明确设置的仅链接限制保持不变。原发起人可在任务详情的“任务信息 → 回复方式 → 修改”中选择直接回复内容或仅发送链接，也可在“个人设置 → 机器人聊天”中设置自己在各会话新发起任务时的默认方式。同一群内的多个岗位机器人共用这份本人偏好，其他群和其他成员不受影响。

保存设置不会增加补充要求或重新执行任务。已完成任务也可以修改以后追问的回复方式；需要再次发出已有成果时，单独点击“发送已有结果”并确认。只修改方式不会自动补发答案。尚未实际发送的消息按当前设置处理，已经提交平台的内容不会改写或自动撤回。

飞书正文采用 Markdown（文本排版语法）消息卡片。任务入口卡片提供“回复方式”按钮；机器人尚未确认卡片操作可用时，该按钮打开网页设置。管理员在飞书开放平台的“事件与回调 → 回调配置”启用卡片回传交互，再从群策机器人的“连接检查 → 测试收发消息”主动发送测试卡片，由已绑定账号点击“确认卡片按钮”。收到有效操作后，新卡片才显示原消息内的选择控件。长连接不需要新增公开地址，回调地址方式继续使用该机器人的签名校验。设置结果仅向操作者提示，原设置卡片随之更新。

在原会话发送独立的“回复方式”可打开本人设置。回复具体任务时，可发送“本次只发链接”或“本次直接回复内容”；“默认仅发送链接”和“默认直接回复内容”修改本人会话偏好。包含这些词语的普通任务正文不会被当成设置指令。

接口均使用当前登录会话与跨站请求保护，写入还需要 `Idempotency-Key`（重复请求识别编号）：

| 地址（前缀为 `/api/v1/enterprises/{enterpriseId}`） | 方法与作用 |
| --- | --- |
| `/chat/reply-preferences` | GET：分页列出本人参加过的机器人会话及偏好 |
| `/chat/reply-preferences/{conversationId}` | GET / POST：读取、保存本人的会话偏好 |
| `/collaboration/tasks/{taskId}/reply-mode` | GET / POST：原发起人读取、保存当前任务回复方式 |
| `/collaboration/tasks/{taskId}/resend-result` | POST：原发起人发送已完成任务的既有结果，不启动执行 |

本次迁移 `V0.4.0.6__新增本人机器人回复偏好.sql` 新增个人偏好表及独立设置版本。接口分别检查任务设置与个人偏好的版本；旧页面提交时返回冲突提示，不覆盖别人或本人在另一处刚保存的选择。卡片操作也核对应用、机器人、来源会话、实际发出的消息与原发起人。
