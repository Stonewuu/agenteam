# JSON 数据助手

上传 `agenteam-json-tools-plugin-1.0.0.jar`（Java 程序包）后，智能体就能使用四个工具处理 JSON（结构化数据文本），完成校验、排版、按路径取值和比较修改。插件只处理传入文本，不读取本机文件、不联网，也不需要配置密钥。

## 安装与使用

适用于已经启用扩展插件功能的 AgenTeam，后端使用 Java 21。

1. 进入插件配置页，点击“安装扩展插件”，上传程序包。
2. 确认名称为“JSON 数据助手”、版本为 `1.0.0`，确认安装。
3. 添加这个扩展来源，填写配置并选中需要使用的工具，保存并发布插件。
4. 在智能体配置里选择刚发布的插件版本，保存并发布智能体。
5. 选择支持工具调用的模型，新建对话，发送下面的测试内容。

| 工具 | 能做什么 |
| --- | --- |
| `json_validate` | 严格校验文本；错误时返回中文说明和可用的行列位置，拒绝重复字段、注释和多余内容 |
| `json_format` | 缩进排版或压缩成单行，保留大整数与小数的数值精度 |
| `json_extract` | 一次提取最多 20 条路径，明确区分字段不存在与字段值为 `null`（空值） |
| `json_diff` | 按字段和数组位置比较新增、删除、修改；超过上限时提示仍有未显示差异 |

配置可保留默认值：缩进 2 个空格、开启字段排序、最多显示 50 处差异。也可改成 4 个空格、保留原字段顺序，差异数量可设置为 1 至 200。

## 可以直接复制的体验内容

```text
请实际调用 JSON 数据助手，完成下面四项任务：
1. 校验新版订单；
2. 格式化新版订单；
3. 提取新版的 /orderId、/customer/name、/trackingId、/missing，说明空值与字段不存在的区别；
4. 比较两版订单，列出每处差异的路径、旧值和新值。

旧版：{"orderId":9007199254740993,"customer":{"name":"张三"},"items":[{"sku":"BOOK","quantity":2,"price":19.90}],"status":"pending"}
新版：{"orderId":9007199254740993,"customer":{"name":"张三"},"items":[{"sku":"BOOK","quantity":3,"price":19.90}],"status":"paid","trackingId":null}

保留完整订单号，不要把空值说成字段不存在。
```

预期结果：订单号保持为 `9007199254740993`；姓名为“张三”；`trackingId` 存在且为空，`missing` 不存在；差异恰好有 3 处：`/items/0/quantity` 从 2 改为 3，`/status` 从 `pending` 改为 `paid`，新增 `/trackingId` 且值为空。示例文件也保存在 `samples/` 中。

还可以发送：

```text
请用插件校验 {"name":"张三",}，告诉我错误位置。
```

```text
请用插件把 {"z":9007199254740993,"a":0.12345678901234567890123456789} 压缩成单行，保留数字精度。
```

## 路径和比较规则

提取工具使用 JSON Pointer（用斜杠分隔字段的标准路径）：`/items/0/sku` 读取数组第一个元素的商品编码，空字符串路径读取全文。字段名本身含 `/` 时写为 `~1`，含 `~` 时写为 `~0`。例如读取 `{"a/b":{"~name":"张三"}}` 中的姓名，使用 `/a~1b/~0name`。不支持通配符或筛选表达式。

提取结果中的 `found` 表示字段是否存在，`json` 返回精确的 JSON 文本。比较结果中的 `before` 和 `after` 同样是 JSON 文本，避免平台或模型把大整数转成不精确的浮点数。

比较忽略对象字段顺序，`1`、`1.0`、`1e0` 视为数值相同。数组按位置比较，结果用于说明差异，不是可直接执行的修改补丁。格式化可能把 `19.90` 显示为 `19.9`，两者数值相同；本工具不保留数字原文的排版。

## 处理范围

每份文本最多 100000 个字符，最多嵌套 64 层，单个数字最多 1000 个字符。结果文本总量有限制，过长时明确提示缩小范围；比较结果的 `truncated` 为 `true` 时表示还存在未显示的差异。请传入完整文本，不包含 Markdown（文本排版语法）的代码围栏。

这些限制针对工具直接输入。智能体还受所选模型的上下文和输出长度限制，大文件需要先截取相关部分。

## 从源码构建

本工程使用 Maven（Java 构建与依赖管理工具）和 Java 21。在仓库 `agenteam-server/` 目录执行：

```powershell
./mvnw.cmd -f agenteam-tool-api/pom.xml install
./mvnw.cmd -f agenteam-plugin-api/pom.xml install
./mvnw.cmd -f agenteam-plugin-api/examples/json-tools-plugin/pom.xml clean verify
```

上传产物为本工程 `target/agenteam-json-tools-plugin-1.0.0.jar`。以 `original-` 开头的文件没有合并解析库，不用于上传。

稳定插件标识为 `agenteam.json-tools`。练习升级时可加 `-Drevision=1.1.0` 生成不同版本；安装新版后需要重新确认插件配置及智能体引用，不会自动切换旧引用。

插件自己的 Jackson（JSON 解析库）已合并并改用独立内部包名，平台接口与 PF4J（Java 动态插件框架）由平台提供。许可与依赖信息见 `LICENSE` 和 `THIRD-PARTY.md`。
